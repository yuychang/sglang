Optimization stack for MXFP4 graph decode

This report explains the retained AMD/AITER optimizations in the kimi-k25-mxfp4-optimizations branch, the switches that control them, their runtime gates, and the additional MLA projection fusion committed with this report.

At a glance

The branch targets Kimi K2.5/DeepSeek-style decode on ROCm gfx950 hardware. The central strategy is to remove redundant launches and data transformations while overlapping routed and shared MoE work. Unsupported shapes and backends retain the existing implementation.

25 tracked files changed in the three committed optimization commits
5,960 → 5,724 reported total GPU kernels for one c4 decode step
+9.04% reported compact-scale throughput gain at concurrency 8

Measurements are taken from the repository optimization note and are not a substitute for a matched benchmark on your deployment.

Execution topology

The separate-shared path keeps the routed and shared TP-local results independent until the next layer. The next layer can consume both buffers in one collective/norm operation. 

graph/main stream:  hidden → router → routed MoE ────────────────┐
                                                               │
dedicated MoE stream: shared MLP ──────────────────────────────┤
                                                               ▼
                         fused two-input all-reduce + residual + RMSNorm
                                                               │
                                                               ▼
                                      next MLA layer
Important: the dedicated MoE stream is separate from the MLA alternate stream. The overlap path requires GPU_MAX_HW_QUEUES >= 5; otherwise it falls back to the standard path to avoid queue-level serialization.

Techniques and switches

Committed

1. Fused grouped top-k shared-column append

AITER grouped top-k writes routed top-k columns and fixed shared-expert columns in the same launch. This removes a separate append kernel while preserving routed renormalization and scaling semantics. SGLang also avoids an unnecessary correction-bias dtype conversion when the input already has the expected dtype.

SGLANG_AITER_FUSED_SHARED_EXPERT_TOPK Defaults to true in the AITER integration. Set it to 0 to use the routed-only result plus the existing append/remap path.
Committed / AITER coordinated

2. Fused route sort and once-per-token MXFP4 quantization

For supported gfx950 graph shapes, the specialized AITER producer combines route sorting with compact MXFP4 activation quantization. Each original token is quantized once instead of once per routed row, producing compact packed FP4 activations and compact E8M0 scales.

SGLANG_AITER_FUSED_DECODE_TOPK_SORT AITER-owned route-sort/quantization switch used by the coordinated stack. Keep it enabled to use the specialized producer; disable it for the conventional route/quant path.
Committed / AITER coordinated

3. Compact-scale GEMM1

The tuned FlyDSL GEMM1 consumes compact token scales directly for graph batches M=8,16,32,64,128. It reuses sorted token IDs already staged in LDS and repacks the needed E8M0 bytes in registers, eliminating standalone compact-to- sorted scale conversion.

SGLANG_AITER_FUSED_DECODE_COMPACT_SCALE Enabled by the retained recipe. Set it to 0 to restore scale conversion. M≤4 deliberately remains on the conventional path because the direct consumer regressed TPOT in measurements.
Committed

4. Shared MLP SiLU×up plus MXFP4 quantization

The separate shared MLP can fuse the SiLU×up activation with dynamic MXFP4 quantization before the down projection. The down projection consumes packed FP4 data and compact E8M0 scales directly, avoiding an intermediate BF16 activation and separate quantization launch.

SGLANG_ROCM_KIMI_MXFP4_FUSE_MLP_ACT_QUANT Defaults to true, but only activates on the ROCm/AITER Kimi multi-stream path with compatible Quark MXFP4 weights. Set it to 0 to restore the existing activation path.
Committed

5. Dedicated MoE stream

Routed experts remain on the graph/main stream while the separate shared expert runs on a dedicated MoE stream. The implementation waits only at the join point and records the shared output for correct allocator lifetime management.

SGLANG_ROCM_USE_MULTI_STREAM Defaults to false. Set it to 1 to opt into the ROCm dual-stream path, provided GPU_MAX_HW_QUEUES >= 5.
Committed

6. Deferred shared add into fused AR/RMSNorm

Instead of immediately adding routed and shared TP-local outputs, the shared result can be carried to the next layer. AITER then consumes routed input, shared input, and residual in one fused all-reduce + residual add + RMSNorm operation.

SGLANG_ROCM_FUSE_SHARED_PARTIAL_AR_RMSNORM Defaults to true inside the already opt-in multi-stream path. Set it to 0 to force the existing local add before the collective.
Committed

7. Tuned one-stage/two-stage collective policy

The fused AR/RMSNorm dispatcher now considers token count, hidden size, TP size, and bytes rather than using one universal byte cutoff. For TP4 and hidden size 7168, the two-input path uses one-stage through M=8 and a partitioned two-stage path for M=16/32.

SGLANG_USE_1STAGE_ALLREDUCE / SGLANG_FUSED_AR_RMS_1STAGE_MAX_BYTES The first force-selects one-stage behavior. The second overrides the automatic byte threshold. The benchmark also exposes --stage and --one-stage-max-bytes.
Committed, default-off feature

8. Fused AR/RMSNorm/MXFP4 producer with activation carrier

The latest committed optimization fuses all-reduce, residual addition, RMSNorm, and MXFP4 quantization. It returns the BF16-normalized result together with packed FP4 data and scales. A one-use carrier attaches those quantized buffers to the BF16 tensor so the dependent shared FC1 can reuse them without another quantization pass. Graph concurrency 4/8/16/32 uses AITER's direct quantizing epilogue; 64/128 uses fused AR/RMSNorm followed by one reusable quantization pass.

--enable-rocm-fused-ar-mxfp4-quant and SGLANG_ROCM_FUSED_AR_MXFP4_QUANT_MODE The CLI flag defaults off. The mode accepts off, event, or optimized; the producer-reuse path requires optimized and the exact graph/shape gates.
Committed

9. Skip identity MLA BMM scaling

MLA BMM weights are converted to BF16 as before, but a scalar scale of exactly 1.0 no longer triggers an elementwise multiplication. Tensor-valued scales and non-identity scalar scales retain the original semantics.

Automatic; no runtime switch The optimization is selected by the scale representation. It is covered by unit tests for identity, non-identity, and tensor-valued scales.
Current commit

10. Fused MLA projection + RoPE + KV-cache write

On the supported Kimi MLA path, AITER's fused FP4 BMM/RoPE kernel now performs the absorbed w_kc projection, applies RoPE, concatenates the latent key components, and writes the KV cache in one grid. The regular cache-save path is skipped because the fused kernel performs the write.

SGLANG_ROCM_FUSE_MLA_PROJECTION_ROPE_CACHE Defaults to true in this commit. Set it to 0 to use the existing projection and cache path. The gate additionally requires HIP/AITER gfx950, graph decode, AITER attention, uint8 w_kc, and the Kimi MLA dimensions.

Switch matrix

The switches below are grouped by ownership. Some route-sort and compact-scale controls are AITER-side controls used by the coordinated SGLang/AITER stack rather than SGLang CLI arguments.

Switch Default Effect Scope / fallback
SGLANG_ROCM_USE_MULTI_STREAM false Enables routed/shared MoE stream overlap. ROCm/AITER; requires at least five hardware queues.
SGLANG_AITER_FUSED_SHARED_EXPERT_TOPK true Lets AITER append fixed shared columns during grouped top-k. AITER top-k path; falls back to append/remap.
SGLANG_AITER_FUSED_DECODE_TOPK_SORT AITER recipe Selects fused route sort plus compact MXFP4 quantization. AITER-owned; conventional route/quant path remains available.
SGLANG_AITER_FUSED_DECODE_COMPACT_SCALE enabled Selects direct compact-scale GEMM1 consumption. Best retained for M≥8; set to 0 to disable.
SGLANG_ROCM_KIMI_MXFP4_FUSE_MLP_ACT_QUANT true Fuses shared MLP SiLU×up with dynamic MXFP4 quantization. Requires compatible Quark MXFP4 weights and multi-stream mode.
SGLANG_ROCM_FUSE_SHARED_PARTIAL_AR_RMSNORM true Defers the shared add into the next fused two-input collective. Supported graph shapes only; local add is the fallback.
--enable-rocm-fused-ar-mxfp4-quant off Enables the fused AR/RMSNorm/MXFP4 producer. Graph-only TP4/EP1 path for M=4,8,16,32,64,128.
SGLANG_ROCM_FUSED_AR_MXFP4_QUANT_MODE optimized Selects comparison mode for the producer/carrier path. The activation-carrier optimization requires optimized.
SGLANG_USE_1STAGE_ALLREDUCE automatic Force-enable or force-disable one-stage fused AR. Automatic policy protects larger batches from the one-stage limit.
SGLANG_FUSED_AR_RMS_1STAGE_MAX_BYTES 128 KiB generic Overrides the automatic byte cutoff. TP4/H7168 has a tuned lookup entry of 512 KiB unless overridden.
SGLANG_ROCM_FUSE_MLA_PROJECTION_ROPE_CACHE true Enables the new fused MLA projection/RoPE/cache-write path. Current commit; unsupported MLA configurations fall back.

Common eligibility gates

Shared-output / collective stack

  • HIP/ROCm AITER on gfx950.
  • Kimi K2.5 Quark/OCP MXFP4 checkpoint.
  • Separate shared expert and TP4.
  • BF16 contiguous hidden states with hidden size 7168.
  • HIP graph capture and a supported decode token count.
  • Next-layer all-reduce fusion available and not final layer.

New MLA projection fusion

  • HIP/AITER gfx950 and AITER attention backend.
  • Decode or idle mode during graph capture.
  • No DSA, experimental LoRA optimization, KV-B LoRA, or DCP.
  • Uint8 absorbed w_kc with a K scale tensor.
  • Kimi MLA dimensions: q-lora 1536, KV-lora 512, Q nope 128, Q/K RoPE 64, V 128.
